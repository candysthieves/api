# Возврат в Personal после истечения подписки

Согласованный вариант: TCP из payments в main, только YooKassa. Заменяет первоначальное предложение о businessExpiresAt; миграция и изменение payment.completed не нужны.

- Scheduler раз в минуту выбирает последние Done-подписки YooKassa с expirationDate <= now. nextChargeDate проверяется в обработчике: null означает смену User на Personal, непустое значение — существующее автопродление.
- До окончания оплаченного срока отмена автосписания не меняет Business.
- Main принимает внутреннюю TCP-команду set-user-personal с userId. Идемпотентно обновляет Business на Personal и подтверждает после записи. Удалённый пользователь считается обработанным.
- При таймауте Processing и явном отказе оплаты: проверить оплаченный срок только последней подписки пользователя; если его нет, дождаться TCP-подтверждения main и только потом сохранить Failed. При ошибке состояние остаётся Processing для повторной обработки. Другие провайдеры не меняют статус User.
- Просроченные Processing обрабатываются поштучно, ошибка одного пользователя не блокирует остальных.
- Последние Failed-подписки YooKassa тоже проверяются scheduler: после окончания сохранённого оплаченного срока этой подписки пользователь переводится в Personal. Failed не запускает повторное списание.
- Оплаченный срок определяется по expirationDate > now независимо от статуса: дата сохраняется после перехода в Processing/Failed. Новая неоплаченная подписка с null expirationDate не продлевает доступ.
- Уточнение от 2026-10-29: учитывается только последняя созданная подписка (createdAt DESC, id DESC), выбранная среди всех записей до проверки статуса и срока. Это правило применяется к current, отмене и проверке оплаченного доступа. После истечения последней подписки старые записи не возвращаются в current и не сохраняют Business, даже если их expirationDate ещё в будущем. История сохраняется.
- Повторные TCP-запросы раз в минуту для истёкших отменённых/Failed подписок допустимы. Таймаут запроса — 5 секунд. Новые очереди и события не вводятся.
- Гонка с новой оплатой и запоздалым Personal принята пользователем; блокировок и версионирования не добавляем.

## Настройка

MAIN_TCP_HOST и MAIN_TCP_PORT задают адрес прослушивания в main и адрес подключения в payments. По умолчанию 127.0.0.1:4004 — для локального запуска и текущего VPS с network_mode: host. Для отдельных контейнерных сетевых пространств указать в main адрес прослушивания, в payments — доступное имя main. Порт внутренний, не HTTP endpoint.

## Проверки

Unit-тесты локального результата: отменённая истёкшая подписка не создаёт платёж; TCP-ошибка не даёт сохранить Failed; повтор после ошибки; сохранение оплаченного доступа; другие провайдеры; изоляция ошибок по пользователям; явный отказ оплаты. Транспорт и простое делегирование TCP не тестируются. Сборки main/payments, lint изменённых TypeScript-файлов. Без commit/push/deploy и изменения рабочих БД.

Проверка выборок на настоящем ClickHouse не выполнена: локальный Docker Engine недоступен, в том числе вне sandbox.
